# OpiOpe V24.5 production candidate

This version is designed as the production-candidate step after V24.4.3.

## Included in this candidate

- Course-first entry: Suomi / Ruotsi
- Role choice per course: student / teacher / free user
- Supabase account creation for all three account paths
- Email-verification callback with safe local redirect handling
- Password reset request and password update pages
- Student dashboard tied to the saved course language
- Teacher application -> pending -> admin approval/rejection -> teacher access
- Server-authoritative teacher and admin checks
- Teacher MFA gate
- Registered free-user sign-in plus no-account free browsing
- Teacher/student class relationship and student progress restrictions
- Finnish/Swedish login errors for the selected course
- Sign-out controls for student and teacher dashboards
- Production environment verification script

## Required production configuration

Create `.env.local` locally and production environment variables in the hosting platform. Never commit secrets.

Required:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` or `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- `NEXT_PUBLIC_SITE_URL=https://opiope.fi`
- `SUPABASE_SERVICE_ROLE_KEY` (server only)
- `RATE_LIMIT_PEPPER` (server only)
- `NEXT_PUBLIC_CONTROLLER_NAME`
- `NEXT_PUBLIC_PRIVACY_EMAIL`

Optional AI features require `OPENAI_API_KEY` / `OPIOPE_AI_MODEL` as documented in `.env.example`.

## Supabase

Apply all SQL files in `supabase/migrations` in timestamp order to a staging project first, then production.

Configure Auth redirect URLs for at least:

- `http://localhost:3000/auth/callback`
- `https://opiope.fi/auth/callback`

The first admin must be created intentionally by a trusted operator; users must never be able to self-promote to admin or teacher.

## Validation

Run:

```bash
npm install
npm run lint
npm run typecheck
npm run build
npm run verify:production
```

With production env loaded, optionally also run:

```bash
npm run verify:production -- --network
```

Then test with three separate test accounts:

1. student signup -> verify email -> student dashboard -> course levels -> progress
2. free signup/login and no-account free path
3. teacher signup -> verify email -> pending page -> admin approval -> teacher login -> MFA -> teacher dashboard

Also test a second student account to confirm it cannot read the first student's data and confirm teachers only see students joined to their own classes.

## Deployment status rule

Do not call the application production-ready until the exact production commit passes lint, typecheck, build, migrations on staging, authentication end-to-end, RLS isolation tests, teacher approval/MFA tests, and HTTPS deployment checks.
